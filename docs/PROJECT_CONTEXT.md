## Product rules
- Tenant = construction company. Account types THEKEDAR (owner — every permission), PM (office), MUNSHI (site, phone OTP). PLATFORM_ADMIN is a separate table.
- **Permissions** decide what a PM / MUNSHI may do: one or more role templates per member (`Role` via `UserRoleAssignment`, `User.roleId` = primary; system ADMINISTRATOR / PROJECT_MANAGER / MUNSHI / ACCOUNTANT / STORE_KEEPER or custom; effective = union of the roles, widest scope, highest limit) + per-user ALLOW / DENY overrides (invitations carry `roleIds` + `permissionOverrides`, applied on accept). Keys `<module>.<resource>.<action>` in `core/auth/permissionCatalog.ts` (single source); field permissions `fields.rates|amounts|profit|contract`; grants carry scope ASSIGNED_PROJECTS / ALL_PROJECTS and optional `maxAmountPaisa`. The old `canSeeFinancials` = the FINANCIAL_BUNDLE overrides (column kept in step, deprecated).
- Tenant always comes from the verified token (`ctx.tenantId`), never headers/query/URL.
- Web = httpOnly cookies; mobile = tokens in body + `Authorization: Bearer`; body `client: "web" | "mobile"`.
- Money BigInt paisa (sent as strings). IDs UUID v7. Times UTC. Phones E.164 `+92…` (mobile via `normalizePkPhone`, office/landline via `normalizePkAnyPhone`).
- Responses `{ success, data, meta? }` / `{ success: false, error: { code, message, details? } }`.
- Office users (plan limit) = active THEKEDAR + PM; Munshis are free; pending PM invites reserve a seat.

## Database & security
- `DATABASE_URL` app_user (RLS) → `withTenant(tenantId, tx => …)` for everything tenant-scoped.
- `DATABASE_ADMIN_URL` app_admin (BYPASSRLS) → `prismaAdmin`, allowed only in `src/modules/auth/**`, `src/modules/platform-admin/**`, `src/jobs/**`, seed, scripts, tests (guard test enforces — it greps for the word, so don't even mention it in comments elsewhere).
- `DATABASE_MIGRATION_URL` superuser → Prisma CLI only.
- RLS: ENABLE + FORCE + `tenant_isolation` policy on every `tenantId` table (`prisma/rls.sql`). New tenant tables need the policy and an explicit `GRANT … TO app_user` in their migration. Composite `(tenantId, id)` FKs for tenant-scoped parents — **but never include a model's own `id` in relation fields** (Prisma then stops generating its default; see `tenant_logo_fk`).
- `prisma migrate dev` refuses non-interactive runs with warnings and `migrate reset` is blocked for AI agents: generate SQL with `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`, hand-edit renames, save as a migration folder, `prisma migrate deploy`.

## Core (src/core, src/config)
env (Zod), logger (redacted; mixin adds tenantId / userId), observability (`core/observability`: `sentry.ts` init / tags / captureError, `scrub.ts`, `analytics.ts` `track()`, `hash.ts` hashed user id; `src/instrument.ts` preload), requestContext (ALS), AppError family, response/asyncHandler/pagination (`paginationQuery`, `skipTake`, `pageMeta`), `http/routeList.ts` (`listRoutes(app)` from the recorded mounts), utils (json BigInt, phone, crypto, slug, dates `isoDateSchema`/`todayIn`, `uuidv7`), auth (`permissionCatalog`, `access` resolution + checks, `accessLoader` cache, `fieldStrip`, jwt), audit `writeAudit(tx, …)`, OpenAPI registry + light-theme Swagger at `/api/docs` with named examples (`jsonBody(schema, examples)`), middlewares.

**Standard chain:** `authenticate → tenantContext → readOnlyGuard → requirePerm(key) → validate → asyncHandler(controller)`. tenantContext resolves the caller's permissions per request (`ctx.access`, cached per user by `User.permVersion` + `Role.version`). Services: `assertPerm / can / scopeAll / assertApprovalLimit` (`core/auth/access.ts`), `assertProjectScope(tx, key, projectId)` / `projectScope(caller, key)` (`projects/access.ts`), field stripping `visible() / stripFields()` (`core/auth/fieldStrip.ts`). Errors `403 PERMISSION_DENIED { permission }`, `403 APPROVAL_LIMIT_EXCEEDED`. New route → pick a key (or add one to the catalogue + templates) and extend `tests/permissions/parity.test.ts` NEW_ROUTES.
**Module layout:** routes / controller (no logic) / service (transactions, audit) / repository (Prisma, takes `tx`) / schema (Zod + types) / docs.

## Known notes
- Access tokens are re-checked on every company request (user ACTIVE, device not revoked, session family alive), so logout/deactivate/revoke cut access at once. Role and permission changes apply on the next request (resolved from the DB, cached per user). Account-type rules stay on `User.role`: MUNSHI hazri ≤ 7 days back, peshgi / wages from site cash only, blind count, own cash only.
- No parallel queries on one connection: inside a transaction use `inSequence([() => …, () => …])` (`core/db/inSequence.ts`), never `Promise.all` on a `tx`. Prisma 7.10's own parallel include loading is serialised by `SerialPgClient` (`core/db/prisma.ts`). `tests/setup/pgConcurrency.ts` fails any test that overlaps queries on one pg connection.
- `npm audit`: leftovers (Prisma CLI `deepmerge-ts`, `exceljs` → `uuid`) and why are in `docs/SECURITY.md` §10. Security overview + pre-launch checklist: `docs/SECURITY.md`. Rate limits: `core/middleware/rateLimit.ts` (env `AUTH_RATE_LIMIT_MAX`, `AUTH_IP_RATE_LIMIT_MAX`, `OTP_SEND_IP_RATE_LIMIT_MAX`, `SYNC_PUSH_RATE_LIMIT_MAX`, `GENERAL_RATE_LIMIT_MAX`); `OTP_TTL_SECONDS` ≤ 600.
- `NODE_ENV=production` refuses to start with `SMS_PROVIDER=console`, `MAIL_PROVIDER=console` or `STORAGE_PROVIDER=local` unless `ALLOW_DEV_PROVIDERS_IN_PRODUCTION=true` (staging). Tests that load env with production must stub that flag (see `tests/auth/cookieFlags.test.ts`).
- Git commits show author "unknown" until `git config --global user.name` is set.
- DB pool: `DB_POOL_MAX` (20) + Prisma `transactionOptions.maxWait` = `DB_TX_MAX_WAIT_MS` (10 s); a transaction that still can't start → `503 SERVICE_BUSY` (Retry-After 1), which the web client retries for GETs.
